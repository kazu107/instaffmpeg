# Insta360 Frame Extractor GUI

Windows 上で Insta360 などの equirectangular 360° 動画から、
任意方向の JPG 連番を切り出すための GUI ツールです。

`ffmpeg` の `v360` フィルタを使って視点変換を行い、必要に応じて
SegFormer ベースのマスク画像も同時生成できます。

## 主な機能

- 入力動画 / 出力フォルダの指定
- `yaw`, `pitch` ごとの複数方向書き出し
- 水平リング生成
- FPS / 画角 / 出力サイズの指定
- 1 回のデコードで全方向を同時書き出し
- デコード済みフレームのロスレスキャッシュ (再実行の高速化)
- 逆再生
- 奇数フレーム時の方向 index 反転命名
- 画像抽出のみ / マスク生成のみ / 両方の切り替え
- SegFormer による空 / 人 / 車 / 木の個別マスク
- マスクの細かさプリセット、除外しきい値、バッチ数、精度 (fp16 / fp32)
- マスク推論は GPU 前処理 + 複数 GPU 並列
- 入力動画プレビュー
  - 高速再生
  - 枠位置優先プレビュー
  - シークバー
  - ウィンドウサイズに追従 (アスペクト比を保って自動フィット)
- 書き出し方向の 3D 球体ビュー
- 設定の自動保存 / 復元

## 動作環境

- Windows 10 / 11
- Python 3.10 以上
- `ffmpeg` / `ffprobe` が PATH に通っていること

高速プレビューを使う場合:

- VLC Desktop のインストール
  - 既定では `C:\Program Files\VideoLAN\VLC\libvlc.dll` を利用
- `python-vlc`

マスク生成を使う場合:

- `transformers`
- `torch`
  - GPU を使うなら環境に合った CUDA 対応版

## セットアップ

### 1. リポジトリを取得

```powershell
git clone https://github.com/kazu107/instaffmpeg.git
cd instaffmpeg
```

### 2. 仮想環境を作成

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

### 3. 基本依存をインストール

```powershell
python -m pip install -r requirements.txt
```

### 4. `ffmpeg` を使えるようにする

以下が通る状態にしてください。

```powershell
ffmpeg -version
ffprobe -version
```

### 5. 高速プレビューを使う場合

VLC Desktop を入れたうえで:

```powershell
python -m pip install python-vlc
```

### 6. マスク生成を使う場合

CPU のみで良ければ:

```powershell
python -m pip install transformers torch
```

GPU を使う場合は、使用環境に合った `torch` を入れてから
`transformers` を追加してください。

## 使い方

### 基本フロー

1. 入力動画を選ぶ
2. 出力フォルダを指定する
3. 書き出し方向を設定する
4. 必要なら FPS / 画角 / 解像度を調整する
5. 必要ならマスク設定を有効にする
6. `実行` を押す

### 書き出し方向

- `yaw`, `pitch` を直接追加 / 更新できます
- `水平リング生成` を使うと一定間隔の方向をまとめて作れます
- 方向セットはタブで複数管理できます

### プレビュー

- `枠位置優先`
  - 再生映像と書き出し方向の枠位置を一致させたい時に使います
- `枠位置優先` を OFF
  - VLC を使った高速再生を優先します
- どちらのモードでも、プレビューはウィンドウサイズに追従して
  アスペクト比を保ったまま表示領域に収まります
- 起動時のウィンドウ最小サイズは UI の実要求サイズから自動で決まります
  - これより小さくはできません (小さくすると操作ボタンが隠れてしまうため)

### 実行モード

- `画像抽出`
  - JPG を生成
- `マスク生成`
  - 既存 JPG または新規生成 JPG に対してマスクを生成
- `フレームキャッシュ`
  - デコード済みフレームをロスレス保存し、次回以降の抽出で再利用します
  - 同じ動画に対して方向セットや画角を変えて何度も抽出する場合に効きます

両方 ON:

- 画像抽出後にマスクを生成

`マスク生成` のみ ON:

- 出力フォルダ内の JPG に対してマスクを作成

## 出力ファイル

### 抽出画像

```text
{動画名}_{frame_index}_{direction_index}.jpg
```

例:

```text
room360_0000_00.jpg
room360_0000_01.jpg
room360_0001_07.jpg
```

- `frame_index` は 4 桁ゼロ埋め
- `direction_index` は方向数に応じてゼロ埋め

### マスク画像

```text
{元画像名}.mask.png
```

例:

```text
room360_0000_00.jpg.mask.png
```

- 白: 使用
- 黒: 除外
- 検出がなかった場合はマスク画像を作りません

## よく使う設定

### 高速に抽出したい

- `CUDAデコードを使う` を ON (GPU が使えるなら)
- 方向数を増やしても抽出時間はほとんど増えません
  - 抽出は 1 プロセスでデコードを 1 回だけ行い、`split` で全方向へ分岐します
  - 実測 (7680x3840 HEVC / 561.8 s / 6 方向 / fps 1.5):
    方向ごとにプロセスを立てる旧方式 867 s -> 180.6 s、出力はバイト一致
  - このため `並列数` は抽出には使われません (UI 上も無効表示)

### 同じ動画を何度も抽出したい

`フレームキャッシュ` を ON にします。

- 1 回目: `fps` を適用した後のフレームをロスレス (utvideo) で保存します
  - split を 1 本増やすだけなので追加のデコードは発生しません
  - 保存は元動画ではなく**出力フォルダの下**の
    `.insta360_frame_cache/` に置かれます
- 2 回目以降: 元動画の代わりにキャッシュからデコードします
  - 出力 JPG は**バイト一致**します (実測 5058/5058 ファイル)
- 実測 (7680x3840 HEVC / 561.8 秒 / 6 方向 / FPS 1.5):

  | | 時間 |
  |---|---|
  | キャッシュ OFF | 180.6 秒 |
  | 1 回目 (作成しながら抽出) | 176.7 秒 (オーバーヘッド無し) |
  | 2 回目以降 (キャッシュから) | **128.0 秒 (1.38 倍)** |

  - 短縮幅は 52 秒ほどです。キャッシュを使うとデコードは速くなりますが、
    今度は v360 の投影計算 (CPU) が律速になるためここで止まります
  - 9.5 GiB のディスクと引き換えに 52 秒なので、必要かどうかは用途次第です
- キャッシュの鍵は (入力パス, サイズ, 更新時刻, FPS) です
  - 動画を差し替えたり FPS を変えると自動で作り直します
  - 画角 / 解像度 / 方向 / 方向数を変えても**同じキャッシュが使えます**
- ディスク使用量は約 12.1 MiB/フレーム
  - 例: 561.8 秒 / FPS 1.5 = 843 フレームで約 10 GiB
- `逆再生` が ON のときは作成しません (既存キャッシュは利用できます)

### マスクを速くしたい

- 既定 (`精度 = fp16`, `バッチ数 = 9`) が最速です
  - 実測 (2133x2133 / 最高 / RTX 3060 + RTX 2060):
    273.4 -> 34.2 ms/枚 (8.0 倍)
  - CUDA が複数あれば自動で全部使います (起動ログに使用デバイスが出ます)
- `バッチ数` は一度に推論するタイル枚数です。指定できるのは 1〜18
  - `最高` は 1 枚あたり 9 タイルなので、9 未満にすると推論が分割されます
  - 上げすぎると VRAM を使います (実測: 18 で約 2.7 GiB)
- `精度`
  - `fp16` (既定): 速い。マスクは輪郭 1〜2 px だけ変わります
  - `fp32`: 従来と同じ数値。過去のマスクと厳密に揃えたい時に
  - 実測差分は全画素の 0.014% で、97% が輪郭から 3 px 以内
    (参考: `最高` から `標準` に変えると 1.19% が変わります)
- `細かさ = 標準`

### マスク境界を細かくしたい

- `細かさ = 高` または `最高`
- `除外しきい値` を調整

### 誤検出を減らしたい

- `除外しきい値` を上げる
  - 指定できるのは 0 より大きく 1 以下です
  - 0 を許すと全面が除外されてしまうため受け付けません
- `空 / 人 / 車 / 木` を必要な対象だけ ON にする
  - 対象は SegFormer (ADE20K) の該当ラベルのみです
    - `車` = `car` のみ。バス / トラック / バン / 自転車は除外されません
    - `木` = `tree` のみ。草 / 植物 / 花は除外されません

## 補足

### マスクモデルのロード

`画像抽出` と `マスク生成` を同時に実行すると、抽出中に SegFormer の
ロードを並行して行うため待ち時間が隠れます (実測 13 秒/デバイス)。

### マスク生成を有効にした直後は再起動が必要です

`マスク生成` を OFF の状態で起動したセッションでは、そのまま ON にしても
実行できません。次のメッセージが出ます。

```text
マスク生成の準備ができていません。
`マスク生成` を ON にしたまま一度アプリを終了し、再起動してください。
```

理由は Windows 固有の DLL 解決順です。`torch` / `torchvision` /
`transformers` は Tk のウィンドウを作る**前**に読み込む必要があり、実測では

- Tk より後に読み込むと、`from_pretrained` が torchvision の C 拡張を
  ロードする時点でアクセス違反 (終了コード 139) になる
- 特にワーカースレッドからモデルをロードする場合は `torch` だけでは足りず、
  `transformers` までメインスレッドで温めておく必要がある
- Tk の後に読み込むと処理自体は通っても**終了時に必ずフォールトする**

という挙動でした。そこで `main()` は保存済み設定の `generate_masks` を見て、
ON のときだけ Tk より先に読み込みます (約 10〜12 秒)。マスクを使わない場合は
この待ち時間は発生しません。

`SegFormerMaskGenerator` を GUI 以外から使う場合も、Tk を作る前に
`preload_mask_backends()` を呼んでください。

- `yaw/pitch` の並び順が基本の `direction_index` になります
- `奇数フレームで方向indexを逆順` を ON にすると、
  奇数フレームのみ方向 suffix の付け方を逆順にします
- 設定は終了時に `.insta360_frame_extractor_gui.settings.json` へ保存されます
